# PART 1. 실행 시 예상되는 문제 (카테고리별)

## 1A. 인코딩, 텍스트 파싱

**R-A1. DXF 특수코드 미처리**
TEXT/MTEXT에는 AutoCAD 포맷 코드가 섞인다: `%%C`(Ø), `%%D`(°), `%%P`(±), `%%U`(밑줄),
MTEXT의 `{\fArial;...}`, `\P`(줄바꿈), `\A1;` 등. 방이름에 이게 섞이면 매칭, 병합이 깨진다.
→ **보완**: 파서 입구에 정규화 함수 1개(`normalize_dxf_text`)를 강제 통과. ezdxf의
`ezdxf.tools.text.plain_text()` / MTEXT `.plain_text()` 사용. 테스트에 코드 포함 fixture.

**R-A2. MTEXT에 담긴 방 라벨**
현 시설은 TEXT 위주였지만(MTEXT 545개는 주기, 범례), 다른 설계사는 방 라벨을 MTEXT로 쓴다.
현 파서는 TEXT만 순회 → 신규 시설에서 방 0개 추출되는 급성 장애 예상.
→ **보완**: 추출기가 TEXT+MTEXT 모두 순회하도록 지금 수정. 프로파일에 `label_entity_types` 필드.

**R-A3. 블록 내부 텍스트 누락**
방 라벨이 블록(INSERT) 내부 TEXT/ATTRIB인 설계 관례도 흔하다(룸태그 블록). modelspace 순회로는 안 잡힌다.
→ **보완**: `entity.virtual_entities()` 또는 ATTRIB 순회를 추출기에 옵션으로. inventory에
"블록 내 TEXT 수" 항목 추가해 신규 시설 프로파일링 때 감지.

**R-A4. cp949 지뢰의 잔존**
zip 파일명 외에도: DXF 내부 `$DWGCODEPAGE`가 ANSI_949인 구형 파일, 폰트(SHX) 의존 특수문자.
ezdxf가 대부분 처리하지만 R12 등 구버전에서 한글 깨짐 가능.
→ **보완**: ingest 시 `doc.header.get('$DWGCODEPAGE')` 기록. 깨진 한글(U+FFFD) 비율을
품질 지표로 자동 산출 — 5% 넘으면 경고.

## 1B. 좌표계, 시트 구조

**R-B1. 시트 배치 가정 붕괴**
"x축 병렬, 간격 126,000"은 이 설계사의 관례일 뿐. 다른 시설: 세로 배치, 파일당 1시트,
격자 배치, 시트 간격 불균일 전부 가능. 타이틀블록 블록명, ATTRIB 태그(`도면명`)도 설계사마다 다름.
→ **보완**: 시트 감지를 x-bin 하드코딩이 아니라 **타이틀블록 클러스터링**으로 일반화
(타이틀 INSERT 좌표들 → 시트 앵커, 방 라벨은 최근접 앵커 귀속). 프로파일에
`title_block_names`, `title_attrib_candidates: [도면명, DWG_TITLE, SHEET_NAME]` 목록.

**R-B2. Paperspace/Layout에만 있는 정보**
현재 modelspace만 읽는다. 일부 도면은 라벨, 주기를 paperspace(레이아웃)에 배치한다.
→ **보완**: inventory가 layout별 엔티티 수를 출력. 0이 아니면 프로파일에 `read_layouts: true`.

**R-B3. 단위, 축척 불일치**
INSUNITS가 mm가 아닌 파일(m, inch), 또는 축척 1/100로 그려진 모델. 거리 임계값(6000mm 등)이 전부 무너진다.
→ **보완**: 절대 mm 임계값을 **텍스트 높이 상대값으로 교체** — 예: `name_match_max_dist = 12 × median_text_height`.
이것 하나로 축척 문제 대부분 흡수. `$INSUNITS` 기록 + 시트 bbox 크기로 sanity check
(건물 폭이 3m나 3km면 경고).

**R-B4. 회전, 미러 시트**
북향 회전 배치, 미러된 증축 도면에서 "이름이 번호 위" 가정이 깨진다.
→ **보완**: above-bonus를 soft 가중치로 유지하되, 매칭 실패율이 임계(20%) 초과 시
방향 가정 없이 재시도하는 2-pass 로직.

## 1C. 기하 (Phase 2 — 최대 리스크 집중 구역)

**R-C1. flood-fill의 문 누수 (leak)**
벽 LINE만으로 방을 닫으면 문 개구부(900~1200mm)로 공간이 새서 방 2~3개가 한 폴리곤으로 붙는다.
buffer(50)로는 안 막히고, buffer(600)로 막으면 복도(폭 1200~1800)가 소멸한다.
→ **보완**: (1) 문 블록 INSERT 위치에 가상 폐쇄선(door seal segment)을 먼저 삽입하고 flood-fill,
(2) 결과 폴리곤이 방 라벨을 2개 이상 포함하면 "누수 의심" 플래그 → 라벨 개수만큼 Voronoi 분할 폴백,
(3) 면적 상한(단일 방 500㎡) 초과 폴리곤 자동 격리.

**R-C2. 이중선 벽체, 해치 벽**
벽이 LINE 2줄(양면)이거나 HATCH 채움이면 union 결과에 얇은 슬리버 폴리곤이 대량 발생.
→ **보완**: union 후 `polygon.buffer(0)` 정화 + 면적 < 0.5㎡ 슬리버 제거. 벽 레이어를
프로파일에서 지정(`wall_layers`)해 노이즈 레이어(가구, 치수선) 원천 배제.

**R-C3. 기둥, 샤프트, 계단이 방을 관통**
방 내부 기둥이 폴리곤에 구멍(hole)을 만들거나 방을 쪼갠다. 계단실 다층 표현이 겹친다.
→ **보완**: shapely Polygon의 interior ring은 면적 계산에서만 빼고 인접 판정에서는 무시.
계단실, 샤프트(EPS/TPS/PD/AV)는 이름 사전으로 태깅해 인접 규칙에서 별도 취급.

**R-C4. 인접 판정의 3대 오류**
(a) 대각 모서리 접촉을 인접으로 오판, (b) 벽 두께 편차로 buffer(150) 미달 → 인접 누락,
(c) 복도가 30개 방과 인접 → 갱의 체인 검증에 노이즈.
→ **보완**: (a) 교차 결과가 Point면 제외, LineString 길이 ≥ 300mm만 인정.
(b) buffer를 벽두께 추정치(층별 median wall gap)의 1.5배로 캘리브레이션.
(c) 인접 엣지에 `shared_edge_length` 속성 저장 — 규칙이 "문이 있을 법한 인접"(길이≥900)만 필터 가능.

**R-C5. 전략 1(방경계 폴리라인)의 함정**
닫힌 폴리라인 중에는 방이 아닌 것(가구 박스, 장비 외곽, 해치 경계, 라벨박스 — 차압도에서
이미 확인됨: RM 레이어 308개 폴리라인이 전부 라벨박스였다)이 대량이다.
→ **보완**: 3중 필터 — 면적 5~500㎡ **AND** 방 라벨 내포 **AND** 다른 후보와 90% 이상
중첩되지 않음(중복 제거). 필터 통과율을 리포트에 기록.

## 1D. 의미 해석 (semantics)

**R-D1. 화살표 방향의 의미 미확정** 현 데이터 최대 의심점
블록 A$C2C2E3906의 rotation이 "고압→저압"인지 "저압→고압"인지, rotation=0의 기준 방향이
블록 정의 좌표계에서 어느 쪽인지 아직 모른다. 반대로 해석하면 **PRES-001이 정확히 반대로 오검출**된다.
→ **보완**: (1) 블록 정의 지오메트리를 열어 화살촉 좌표로 기준 방향 산출
(`doc.blocks[name]` 순회 — Stage 2 진입 전 필수 태스크로 승격),
(2) 명백한 케이스 3개(제조실→복도)로 부호 검증, (3) 발주처 확인 question 등록. 3중 확인 전 규칙 가동 금지.

**R-D2. TA 값 단위 (기존 question #1)**
90~300 범위 → CMH(급기량)로 추정되나 확정 불가. Pa로 오해석하면 차압 규칙 전체 오염.
→ **보완**: 확정 전까지 `ta_value_raw`로만 저장, 어떤 규칙도 참조 금지. 스키마에 `ta_unit` 필드를
프로파일에서 주입하는 구조로.

**R-D3. 방이름 표기 변형**
`(N)` 접두(신축), `A`/`B` 접미(구역), 괄호 번호 `(3115)`(기존동 참조?), `-1` 접미(분할실),
동일 이름 다수(복도 × N개). 이름 기반 로직(갱의 체인, Grade 휴리스틱)이 흔들린다.
→ **보완**: `room_type` 정규화 사전(`탈의|갱의|샤워|전실|복도|계단|세척|보관|공정...` → 표준 타입 enum)을
`rules/room_taxonomy.yaml`로 분리. 이름→타입 매핑 실패 목록을 리포트에 노출해 사전을 증분 보강.
**괄호 번호의 의미는 question 등록** (기존동 표기로 의심 — 맞다면 신축/기존 필드 분리 필요).

**R-D4. Grade 휴리스틱의 한계**
이름 서열 휴리스틱(제조실>전실>복도)은 "CNC 복도 vs D급 복도"를 구분 못 한다. PRES-001
false positive의 주범이 될 것.
→ **보완**: Grade 확정 전 PRES-001은 severity를 critical→warning으로 강등 + 리포트에
"휴리스틱 기반" 워터마크. Grade 데이터 수령 즉시 재실행하는 절차를 ONBOARDING 문서에.
추가 삼각측량: 화살표 방향 그래프에서 위상 정렬 → 압력 서열을 역산해 이름 휴리스틱과 대조
(둘이 충돌하는 방 = 최우선 검토 대상).

**R-D5. 방번호 체계 가정 붕괴**
"첫자리=층"은 이 시설 관례. 3자리, 알파벳 혼합(R-101), 층 접두 없는 체계 전부 존재한다.
→ **보완**: 층 판정을 (번호 규칙, 시트 귀속) 2소스 투표제로 이미 설계했으니, 프로파일에
`floor_from_number: {enabled, digit_index, mapping}` 스위치화. 두 소스 불일치율을 품질 지표로.

## 1E. 데이터, 성능, 운영

**R-E1. DWG↔DXF 변환 손실**
제공된 dxf가 어떤 변환기로 만들어졌는지 모른다. 변환 과정에서 ATTRIB 소실, proxy entity
(ACAD_PROXY_ENTITY — 전용 앱 객체) 잔존 가능. dwg 원본과 dxf가 불일치할 수 있다.
→ **보완**: dwg/dxf 쌍이 모두 있으면 **쌍 교차검증**(아래 PART 3 X-7). proxy entity 수를
inventory에 포함 — 많으면 ODA File Converter로 재변환 요청.

**R-E2. 대형 파일 성능, 메모리**
65만 엔티티 × 반복 순회 = 세션 타임아웃. ezdxf 로드 자체가 수 GB 될 수 있다.
→ **보완**: (1) ingest 1회 순회에서 필요한 전 필드를 SQLite 캐시가 아닌 **PostgreSQL raw_entities
테이블**(layer, type, x, y, text, block)로 덤프 — 이후 모든 분석은 SQL로. (2) 시트 bbox 단위 처리.
(3) `ezdxf.recover` 모드는 손상 파일에만 (2~3배 느림).

**R-E3. 멱등성 깨짐**
재실행 시 Neo4j 중복 노드, DB 중복 행 → 통계 오염.
→ **보완**: 모든 적재는 `(facility_id, run_id)` 스코프 delete-then-insert. 유니크 제약
`(facility_id, run_id, room_no)` DB 레벨 강제. CI에 "같은 입력 2회 실행 → 결과 동일" 테스트.

**R-E4. run 간 비교 불능**
코드를 고치면 추출 결과가 달라지는데, 어느 방이 왜 달라졌는지 모르면 회귀를 못 잡는다.
→ **보완**: `gxpai diff <run_a> <run_b>` 커맨드 — 방 단위 추가/삭제/필드변경 목록.
**기준 시설 대조 원칙**: 현 시설(내용고형제)을 영구 회귀 기준으로 삼아 모든 코드 변경 후 diff 확인(변경 전후 결과가 바뀌면 안 됨).

**R-E5. CSP 배치의 infeasible 침묵**
OR-Tools가 해 없음을 반환할 때 어떤 제약 조합이 원인인지 알 수 없으면 디버깅 불능.
→ **보완**: 제약을 그룹별로 켜고 끄는 이분탐색 진단 모드(`--diagnose`) 내장. hard 제약 최소화,
가능한 모든 것을 soft(페널티)로.

**R-E6. LLM 파서(Stage 4) 환각**
질의서에 없는 방을 생성하거나 면적을 지어낸다.
→ **보완**: 필드별 근거 인용(원문 스팬) 강제 출력 + 근거 없는 필드는 null. 골드셋 10건
정밀도 측정 전 실전 투입 금지. 파싱 결과는 반드시 사람 검토(diff 뷰) 통과 후 DB 적재.

| S-9 | dwg와 dxf 쌍의 내용 동일성 | 엔티티 수, TEXT 수 비교 (dwg는 ODA converter로) | 미점검 |
| S-10 | 도면 개정 흔적 (revision cloud, 구버전 잔재 레이어) | inventory에서 `*-OLD`, `REV*`, frozen/off 레이어 확인 — frozen 레이어 텍스트를 추출하면 유령 방 생성 | 미점검 |

**S-10 보충**: 현재 파서는 레이어 on/off/frozen 상태를 무시한다. `doc.layers.get(name).is_frozen()`
체크를 추출기 공통 필터로 추가할 것. 유령 방(삭제된 구설계 라벨)은 가장 잡기 어려운 오염원이다.

# PART 3. 교차검증 매트릭스 (전 경우의 수)

> 원칙: **독립된 두 소스가 같은 값을 가리키면 신뢰, 다르면 플래그.** 모든 교차검증은
> 자동화해 리포트의 "정합성" 섹션에 상시 출력한다. 사람은 플래그만 본다.

## 3.1 도면 내부 (single-drawing)
- **X-1 번호 무결성**: 층별 방번호 연속성(결번 목록), 중복 검출, 접미(-1) 계열 정합
- **X-2 라벨-기하 정합**: 방 라벨 좌표가 자기 boundary 폴리곤 내부에 있는가 (밖이면 매칭 오류 신호)
- **X-3 면적 텍스트 대조**: 도면에 면적 TEXT가 있으면(현 데이터엔 없음, 타 시설 대비) 폴리곤 계산치와 ±5% 비교
- **X-4 라벨박스-텍스트 대응**: 차압도 라벨박스(308 폴리라인) 수 vs 번호+이름 텍스트 수 — 박스만 있고 텍스트 없는 곳 = 누락 라벨

## 3.2 도면 간 (cross-drawing) — 같은 시설
- **X-5 평면도 ↔ 차압도**: 방번호 집합 차이(현재 17방), 이름 불일치(현재 4건) [가동 중]
- **X-6 평면도 ↔ HVAC**: AHU 존에 속한 방이 평면도에 존재하는가
- **X-7 DWG ↔ DXF 쌍**: TEXT 수, 내용 해시 비교 (변환 손실 감지)
- **X-8 DXF ↔ PDF**: PDF를 300dpi 래스터화 → (a) 방번호 OCR로 집합 대조(보조),
  (b) SVG 오버레이 시각 대조 — 우리 SVG를 PDF 위에 반투명으로 겹친 이미지를 리포트에 자동 삽입,
  사람이 무작위 5방만 확인하는 **표본 검수 프로토콜**
- **X-9 설계개요 ↔ 기하 합계**: 층별 폴리곤 면적합 vs 연면적/층별면적 표 (±15%, 벽체분 보정계수 프로파일화)
- **X-10 차압도 ↔ HVAC**: 화살표가 있는 방은 AHU 서비스 존에 속해야 함 (비공조 구역에 차압 화살표 = 이상)

## 3.3 논리, 물리 법칙 (domain invariants)
- **X-11 압력 DAG 검증**: PRESSURE_OVER 그래프에 사이클이 있으면 물리적으로 모순 (A>B>C>A 불가)
  → 사이클 = 화살표 오추출 or 방귀속 오류의 강력한 신호. **규칙 이전의 데이터 품질 게이트로 사용**
- **X-12 위상정렬 ↔ Grade 서열**: 압력 위상순서와 Grade(또는 이름 휴리스틱) 서열의 순위상관(Spearman)
  — 낮으면 둘 중 하나가 틀렸다는 뜻. 충돌 방 목록 자동 산출
- **X-13 갱의 체인 존재성**: 모든 제조실은 CNC까지 탈의→갱의→전실 경로가 그래프상 존재해야 함
  (violations이기 전에 추출 완결성 검증이기도 함)
- **X-14 고립 노드**: 인접 엣지 0개인 방 = boundary 실패 신호
- **X-15 면적 분포 outlier**: 방 타입별 면적 분포에서 3σ 밖(0.5㎡ 전실, 400㎡ 복도) 플래그

## 3.4 방법 간 (inter-method)
- **X-16 boundary 전략 교차**: 같은 방을 전략1과 전략3 양쪽으로 얻으면 IoU 계산 — IoU<0.8이면 검토
- **X-17 층 판정 투표**: 번호 접두 vs 시트 귀속 불일치율 [설계 반영됨]
- **X-18 장비 귀속 교차**: nearest vs contains 결과 불일치 목록
- **X-19 LLM 판독 대조** (AlexAI SVG 아이디어의 검증 전용): 층 SVG를 LLM에 주고
  "방번호-이름 목록을 읽어라" → 파서 결과와 diff. 파서가 놓친 라벨(블록 내부, MTEXT)을
  LLM이 잡아내는 **누락 감지기**로 사용. 비용 때문에 신규 시설 온보딩 시 1회만
- **X-20 재현성**: 동일 입력 2회 실행 결과 해시 동일 (CI 상시)
- **X-21 라운드트립**: export DXF → 재ingest → room 집합 동일 (Stage 3 이후 CI)

## 3.5 사람 개입 (human-in-the-loop, 최소비용 설계)
- **X-22 골드셋**: 3F에서 20방을 수작업 완전 라벨링(번호, 이름, boundary, 인접, Grade) →
  추출기별 precision/recall 산출. **골드셋은 코드 수정과 무관하게 불변** — 유일한 절대 기준점
- **X-23 표본 검수 프로토콜**: 리포트마다 무작위 5방 오버레이 확인 (X-8), 소요 5분.
  발견 오류는 error taxonomy에 기록
- **X-24 컨설턴트 검수**: violations 결과에 accepted/false_positive 판정 → DB status 반영
  (Stage 4 학습 원료)

# PART 4. 부족한 점과 보완 방법론 (시스템 차원)

## 4.1 신뢰도 체계 (confidence framework)
모든 추출 레코드에 0~1 confidence를 산출하는 규칙을 통일한다:
```
room.confidence = w1, (매칭거리 정규화) + w2, (층판정 일치) + w3, (boundary method 등급)
                + w4, (교차검증 통과 수 / 적용된 검증 수)
```
- confidence < 0.6 → review_status='needs_review' 자동 큐잉
- 리포트 첫 페이지 = confidence 히스토그램. **"몇 % 확실한가"를 항상 말할 수 있는 시스템**이
  납품 신뢰와 포트폴리오 설득력의 핵심이다.

## 4.2 임계값 자동 캘리브레이션
절대 mm 상수(6000, 800, 150...)를 전부 파생 상수로 교체:
- 텍스트 관련 → `k × median_text_height` (시설별 자동 산출)
- 기하 관련 → `k × median_wall_gap` (벽 이중선 간격 추정)
- 프로파일에는 k(배율)만 저장. 시설이 바뀌어도 스스로 적응한다.

## 4.3 에러 분류학 (error taxonomy)
발견되는 모든 오류를 `docs/ERROR_TAXONOMY.md`에 유형화: {누락, 오매칭, 유령(구버전 잔재),
분할(한 방이 둘로), 병합(두 방이 하나로), 오방향(화살표), 오단위}. 유형별 카운트가
줄어드는 추세 그래프 = 품질 개선의 증거 (포트폴리오 지표).

## 4.4 데이터 계약 (data contracts)
파이프라인 단계 사이에 JSON Schema/pandera 검증을 삽입 — extract 출력이 계약 위반이면
graph builder가 받기 전에 실패. "쓰레기가 조용히 하류로 흐르는 것"이 파이프라인 최악의 장애 유형.
DB 적재 후에도 assertion 세트(행수>0, null 비율, 유니크) 자동 실행.

## 4.5 회귀 방어 3층
1. 합성 fixture 단위테스트 (빠름, 매 커밋)
2. 기준 시설 diff (현 실데이터, 매 PR) — R-E4
3. 골드셋 P/R 리그레션 (매 태그) — X-22
셋 중 하나라도 악화되면 머지 금지. 약한 모델이 작업할수록 이 3층이 품질을 지킨다.

## 4.6 Grade 부재의 구조적 보완 (수령 실패 대비 플랜 B)
Grade DXF를 끝내 못 받는 경우: **3소스 투표로 Grade 추론** —
(1) 이름 사전 휴리스틱, (2) 압력 위상정렬 서열(X-12), (3) AHU 조닝(같은 AHU = 같은 Grade 경향).
3소스 일치 방만 Grade 확정, 불일치 방은 'unknown'으로 정직하게 출력. 추론 Grade임을
리포트에 명시 — 컨설턴트가 unknown만 채우면 되는 워크플로가 오히려 실무적으로 팔린다.

## 4.7 화살표→압력관계 도출의 견고화 (R-D1 심화)
1. 블록 정의에서 화살촉 방향 벡터 확정 (필수 선행)
2. 화살표 위치에서 방향 벡터로 ±레이캐스팅 → 양쪽에서 처음 만나는 방 폴리곤 2개 = (from, to)
   — "최근접 라벨" 방식보다 경계 걸침 케이스에 강함
3. boundary 없는 구간만 최근접 2방 폴백 (approx 플래그)
4. X-11 DAG 검증을 적재 직후 실행 — 사이클 발견 시 해당 화살표들 격리
