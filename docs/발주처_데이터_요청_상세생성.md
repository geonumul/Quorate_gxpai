# 발주처 데이터 요청 리스트 - 상세시공도 자동생성 학습용 (2026-07-03)

목표: AI가 상세시공도를 거의 완성 수준으로 생성 → 자동 규정검토 → 사람은 최종 체크+날인만.
이를 위한 학습·구축 데이터를 발주처에 요청한다. **핵심 원칙: PDF가 아니라 native CAD(DWG/DXF) +
레이어·블록 표준.** 벡터 데이터라야 생성이 가능하고, 그들의 표준 심볼을 그대로 써야 "똑같이" 나온다.

우선순위: 0(법률) → 1(도면 코퍼스) → 2(CAD 표준) → 3(요구조건 쌍) → 4(수정이력) → 5(규정).

---

## 0. 전제 - 법률·포맷 (이게 먼저 확정돼야 함)

| 항목 | 왜 필요 | 스펙 |
|---|---|---|
| **AI 학습·파생생성 사용 동의(서면)** | 실도면 저작권이 원 설계사무소일 수 있음. 학습·변형·생성에 쓸 권리를 명문화(GEN-L1) | 사용 범위·소유권 서면 |
| **데이터 반출/클라우드 학습 가능 여부** | 외부 GPU·API로 학습 시 반출 조항 위반 위험(GEN-L2) | 반출 가능/익명화 조건 |
| **Native 포맷 제공** | PDF·변환 DXF는 XREF·블록·레이어가 깨져 학습 불가(우리가 겪음: 좌표계 혼재) | **원본 DWG** + 참조된 XREF·블록 전부 |

## 1. 도면 코퍼스 (학습의 본체) - 많을수록 좋음

| 항목 | 왜 필요 | 스펙 |
|---|---|---|
| **여러 프로젝트/시설의 전체 도면 세트** | 생성 모델은 다수 사례가 있어야 학습됨. 시설 1개(N=1)로는 불가 | 가능한 많은 시설(수십~수백동), 각 프로젝트 전 도면 |
| **모든 도면 종류** | 상세도까지 생성하려면 상세도를 학습해야 함 | 평면도·청정도구분도·차압도·동선도·HVAC·전기·배관·소방·단면도·**상세도(벽단면·패널조인트·계단·화장실·문/창호)** |
| **다양한 건물 유형** | 도메인 일반화 | OSD·주사제·원료(API)·포장 등 유형별 |
| **층별 전체** | 층 간 정합·반복 학습 | 지하~옥탑 전 층 |

## 2. CAD 표준·라이브러리 (★상세도 "똑같이"의 핵심)

| 항목 | 왜 필요 | 스펙 |
|---|---|---|
| **레이어 표준(도면 작성 기준)** | 각 레이어가 뭘 뜻하는지 알아야 구조화·생성 가능. 없으면 역공학 | 레이어명·선종·색·용도 규정서 |
| **블록·심볼 라이브러리** | 그들 표준 심볼(문·장비·기구·그리드버블·해치)을 그대로 써야 상세가 동일 | .dwg 블록 파일 전부 |
| **표준 상세도(디테일 라이브러리)** | 배치→상세 자동화의 재료. 파라메트릭 규칙으로 만들 원본 | 크린판넬 단면·문/창호 상세·바닥/천장·조인트 등 |
| **도면 양식(표제란) 템플릿** | 시트 자동 생성 | 표제란 .dwg 템플릿 |
| **치수·주기(NOTE) 표준** | 자동 치수·일반주기 생성 | 표준 주기 문구·치수 스타일 |

## 3. 요구조건 ↔ 도면 쌍 (조건부 생성의 입력측)

| 항목 | 왜 필요 | 스펙 |
|---|---|---|
| **실 목록·면적표(room program)** | "요구 → 도면"의 입력. 쌍이 있어야 조건부 생성 학습 | 프로젝트별 실 목록·면적·수량 |
| **실별 데이터 시트** | 실별 등급·차압·온습도·환기횟수·마감을 생성 조건으로 | 청정등급표·room data sheet |
| **공정 흐름도** | 배치를 결정하는 공정 시퀀스 | 제조 공정 flow |
| **장비 리스트** | 장비 배치·유틸리티 생성 | 장비명·치수·유틸리티 |

## 4. 수정이력·품질 데이터 (★학습 최고급 - 사람 개입 축소의 원료)

| 항목 | 왜 필요 | 스펙 |
|---|---|---|
| **도면 수정 이력(before/after)** | "전문가가 무엇을 고치는가" = 사람 리뷰를 학습해 개입을 줄이는 핵심 신호 | rev별 버전 파일 |
| **검토 의견·마크업** | 무엇이 지적됐는지 = 오류 패턴 학습 | 검토서·redline |
| **준공도(as-built)** | 설계 vs 시공 차이 학습 | as-built DWG |

## 5. 규정·검수 기준 (자동 규정검토 = 심판)

| 항목 | 왜 필요 | 스펙 |
|---|---|---|
| **적용 규정 목록·해석** | 자동 규정검토의 근거(별표17·PIC/S·ISPE·내부기준) | 조항 + 내부 해석·체크리스트 |
| **GMP 검수 기준** | 심판 규칙 확정 | 컨설턴트 검수 항목 |

## 왜 이 순서인가 (한 줄 논리)
Native CAD + 레이어/블록 표준(1·2)이 있어야 **그들 심볼로 벡터 상세도를 생성** → 요구조건 쌍(3)으로
**조건부 생성** → 수정이력(4)으로 **사람 개입을 학습해 축소** → 규정(5)으로 **자동 검토**. 마지막에
사람이 최종 체크+날인. 데이터가 충분하면 이 파이프라인이 성립한다(발주처가 데이터 공급 가능하다는 전제).

## 발주처에 강조할 3가지
1. **PDF 말고 원본 DWG**(+ XREF·블록). 변환본은 학습 불가.
2. **레이어·블록·상세 표준 라이브러리** - 이게 "실제와 똑같은 상세"의 열쇠.
3. **수정 이력** - 사람 개입을 줄이는 학습의 최고급 재료.
