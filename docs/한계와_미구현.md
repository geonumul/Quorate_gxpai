# 현재 한계·미구현·데이터 대기 (2026-07-03 기준)

이 문서는 지금 엔진이 **무엇을 못 하는지, 무엇이 데이터가 없어 불가능한지, 어떤 한계가 있는지**를
숨김없이 적는다. 목적은 정직성이다 - 되는 것만 보여주고 안 되는 것을 감추면, 발주처가 나중에
"왜 이게 안 되냐"에서 신뢰를 잃는다. 지금 다 적어두면 그게 그대로 요청 목록이자 로드맵이 된다.

관련 문서: 발주처에 무엇을 요청할지 → `docs/발주처_요청사항.md` · 데이터 오면 켤 작업 → `docs/데이터_대기_작업.md`
· 진행상태 → `docs/PROGRESS.md` · 리스크 총람 → `docs/RISK_METHODOLOGY.md`

현재 실측(기준 시설 = 내용고형제, run 1개 기준):
번호방 111 · 무번호공간 52 · 장비 418(방 귀속 376 / 미귀속 42) · AHU 20 · 인접 283(근사) ·
차압 화살표 98(방 귀속 0) · TA 값 98(단위 미상) · 청정등급 0 · 방 면적 0 · 위반 20(LBL-001 3 · LBL-002 17).

## 1. 지금 작동하지만 "근사·잠정"이라 신뢰에 주의할 것

이건 돌아가긴 하는데, 결과를 100% 믿으면 안 되는 항목이다.

- **방 인접(283개)은 근사다.** 실제 벽·문 기준이 아니라 "방 라벨끼리 가장 가까운 3개"를 이었다.
  벽으로 막힌 두 방이 좌표상 가까우면 인접으로 잘못 볼 수 있고(오탐), 좁은 통로로 이어진 먼 방은
  놓칠 수 있다(누락). → 방 경계 폴리곤이 생기면 정밀 인접으로 교체 필요.
- **장비의 방 귀속(376/418)도 근사다.** 경계가 없어 "가장 가까운 방"에 붙였다. 42개는 아예 못 붙였다.
  경계가 생기면 "방 안에 포함(contains)"으로 승격해야 정확해진다.
- **차압 화살표(98개)는 방향(각도)만 확정, 의미는 미확정.** 화살촉이 "고압→저압"을 뜻하는지
  발주처 확인 전이다. 그래서 어느 방이 고압/저압인지(방 귀속)를 아직 채우지 못했다(귀속 0).
- **GMP 규칙의 법적 근거 조항은 컨설턴트 미검수다.** 규칙 파일의 "별표17 / PIC-S Annex 1" 인용과
  잠정 기준값은 초안이며, GMP 전문가 검토 전까지 규정적 정확성을 보장하지 않는다.

## 2. 지금 안 되는 것 (미구현)

- **방 경계 폴리곤·면적**: 방을 점(라벨 위치)으로만 안다. 면적(area_m2) 전부 비어 있음(0/111).
  → 면적 기반 규칙, 공간 겹침 검사, 정밀 인접 모두 불가.
- **압력·등급 규칙 실제 작동**: PRES-001(압력 역전)·ADJ-001(등급 인접 금지)은 코드·시험은 끝났지만
  게이트로 잠가 실제로는 0건만 낸다. 데이터·검수 전 오작동을 막기 위함(의도된 미작동).
- **PRES-002(차압 기준값 미달)·ADJ-002(갱의 체인 누락)**: 코드 자체가 없다(스펙만).
- **Neo4j 압력 관계(PRESSURE_OVER)**: 화살표 의미 미확정이라 그래프에 안 만든다.
- **PostGIS 공간질의**: 미도입(면적·폴리곤 생기면 도입).
- **`gxpai diff`(두 실행 결과 비교)·`generate`(배치 생성)·`export dxf`**: 명령 골격만 있고 내용 없음.
- **평면도 벽 기반 경계 자동생성(flood-fill)**: 데이터 없이도 시도 가능한 최고난도 작업인데 아직 미착수.
- **정밀도·재현율 회귀셋(골드셋)**: 정답 라벨 세트가 없어 수치적 품질 지표를 아직 못 낸다.
- **Stage 3(생성)·4(지능화/LLM·RAG)·5(API 서버)**: 미착수(로드맵 상 후속).

## 4. 데이터(도면) 자체에서 온 한계 - 이건 우리가 못 바꾼다

- **1·2층에는 GMP 번호방이 없다.** 번호는 3·4층에만 매겨져 있다(도면 규칙). 정상이며 누락 아님.
- **무번호 공간 52개**(복도·계단·샤프트 등)는 번호가 없어, 번호 기준 검사(LBL 등)에서 빠진다.
- **평면도에 좌우 반전된 도형(OCS 미러) 3947개**(R-F2): 경계 작업 시 좌표를 되돌리는 처리가 선행돼야
  한다. 안 하면 경계가 뒤집힌다. 지금은 경계를 안 만들어 문제 없지만, 착수 시 반드시 처리.
- **정렬 텍스트 774개**(R-F1): 이미 반영(정렬점으로 위치 계산). 남은 리스크 아님.

## 5. 구조적·방법론적 한계 - 알면서 감수하는 것

- **검사 결과는 "위반 후보"이지 법적 최종 판정이 아니다.** 사람이 반드시 검토한다. 자동화는 놓칠 곳을
  줄이는 도구지 판정 주체가 아니다.
- **규칙은 데이터(YAML), 실행은 코드로 분리**했다. 규칙 추가는 쉬우나 규칙의 규정적 정확성은
  GMP 컨설턴트 책임 영역이다(우리는 정확히 실행할 뿐).
- **실검증은 단일 시설(내용고형제) 하나뿐이다.** 다른 시설은 온보딩 때 프로파일(레이어명·번호체계)을
  다시 맞춰야 하고, 그 전엔 정확도를 보장 못 한다. 합성 시설로 "코드 수정 0줄 온보딩"은 검증했으나
  실제 타 시설 데이터로는 미검증.
- **수치 판정은 결정론 코드가 하고 LLM은 규칙 해석에만 쓸 계획**(환각으로 인한 오판 방지). 아직 LLM은
  도입 전이다.

## 6. 멈춤 지점 - 여기부터는 진짜 데이터가 있어야 진행

데이터 없이 더 할 수 있는 것: 평면도 벽 기반 경계 시도(4장 OCS 미러 처리 선행), Stage 3 생성 설계,
리포트·질의 보강. 그 다음은 발주처 자료 수령 후: 정밀 경계·면적, 압력·등급 규칙 실제 활성화,
차압 단위 기반 규칙, 1·2층 검사. 이 지점에서 자료를 요청하고 대기한다.
