# 발주처 요청, 확인 사항 (Client Data & Confirmation Requests)

이 문서는 GXPAI 도면 자동화 엔진을 계속 진행하기 위해 발주처에 **받아와야 할 데이터**와
**확인받아야 할 사항**을 빠짐없이 정리한 것이다. 각 항목은 "무엇을 / 왜 필요한지 / 지금 없으면
무엇이 막히는지 / 현재 임시 처리 / 우선순위"로 적었다. 리드타임이 길므로 우선순위 높은 것부터
가능한 한 빨리 요청하는 것이 좋다.

우선순위 표기: **[긴급]** 이게 없으면 다음 단계 자체가 막힘 / **[중요]** 품질, 정확도에 직접 영향 /
**[법률]** 코드 작성보다 먼저 답을 받아야 하는 계약, 권리 문제 / **[운영]** 향후 효율, 견적용.

이 문서 하단의 "요청 요약표"만 떼서 그대로 발주처에 보내도 된다.

---

## A. 도면, 데이터 (엔진 진행에 직접 필요한 파일)

### ~~A-1. 청정등급(Grade) 도면 - [긴급]~~ → **철회함 (2026-07-14)**

> **이 요청은 잘못됐다. 보내지 마라.**
>
> 우리는 "방마다 등급이 표기된 도면"을 **긴급**으로 요청하려 했다. 그런데 1차 미팅(2026-07-09)
> 녹취를 다시 읽어 보니 대표님이 **이미 답을 해 뒀다**:
>
>   *"방마다 (등급을) 하지는 않고 **구역**으로 해요. 'a부터 b까지는 그레이드 B' 이렇게
>    해 주면 AI가 알아서 하는 거지."*
>
> 즉 **도면에 방별 등급이 없는 게 정상이다.** 우리 기준 시설의 등급 표기가 0건인 것은
> **도면 결함이 아니라 업계 관행**이다. 그걸 "최대 병목"이라고 문서에 써 왔다 — 틀렸다.
>
> 이 요청을 그대로 보냈으면 **우리가 이 업을 모른다는 인상**을 줬을 것이다.

**대신 이렇게 한다** (구현 완료 — `gxpai/core/grade_zones.py`):

1. **제형이 기본 등급을 정한다.** 내용고형제 → **D**. (대표님: "내용고형제는 기본이 D")
2. 예외 구역만 **사람이 지정한다** — 프로파일에 `grade_zones` 로
   *"3101~3120 은 C"* 처럼 **구역 단위**로 적는다.
3. 복도, 기계실, 보관소 등 **관리 외 구역은 등급을 주지 않는다**(`None` 으로 둔다).
   0 이나 'NC' 로 채우면 "등급이 없다"가 "등급이 최하다"로 둔갑한다.

현재 기준 시설: **110개 방이 D**, 복도, 기계실 등 **53개 방은 등급 없음**.

**그래서 발주처에 물을 것은 이것 하나뿐이다** →
  *"기본 등급(D) 말고 **다르게 관리하는 구역**이 있습니까? 있다면 방번호 범위로 알려 주세요."*
  (`docs/20_발주처_확인요청서.md` 에 정식 문항으로 들어 있다)

### A-2. 벽체 위치가 담긴 원본 파일 (XREF 외부참조 원본) - [긴급]
- **무엇을**: 차압 도면 등에서 벽체(벽 선)를 외부참조(XREF, 다른 도면 파일을 불러다 쓰는 방식)로
  가져오고 있는데, 그 **불러오는 원본 도면 파일**. 파일명에 XR_3rd, XR_4th 같은 참조가 걸려 있다.
- **왜 필요한지(상세)**: 방의 실제 모양, 면적을 계산하고 "어느 방이 어느 방과 벽을 맞대고 붙어
  있는지"를 정확히 판정하려면 벽 선의 좌표가 필요하다. 지금은 그 벽 정보가 외부 파일에 있고
  우리 손에 없어서, 방을 점(위치)으로만 알고 실제 경계(닫힌 도형)를 그리지 못한다.
- **없으면 막히는 것**: 방 경계 폴리곤(면적, 모양) 추출, 정확한 인접 판정, 장비의 방 소속을
  point-in-polygon으로 확정하는 작업이 모두 막힌다. 현재 인접은 "가까운 방 3개" 근사로만 하고 있다.
- **현재 임시 처리**: 방 경계 없이 최근접 근사로 인접을 계산 중(리포트에 근사임을 명시). 원본
  수령 시 정식 경계, 면적 계산으로 승격 예정.
- **부탁 형태**: XREF로 참조되는 원본 DXF/DWG 전부. 또는 벽체가 포함되도록 "바인드(bind)"해서
  하나로 합친 도면. (변환 도구 ODA File Converter로 처리 가능)

### A-3. 1층, 2층 차압(기압) 도면 - [중요]
- **무엇을**: 방들 사이 기압 차이(차압)를 표시한 도면 중 1층, 2층 것. 현재 받은 것은 3층, 4층
  (M0-014~015)뿐이다.
- **왜 필요한지(상세)**: 압력 규정 검사는 층별로 이뤄진다. 1, 2층 차압 도면이 없으면 그 두 층은
  압력 검사를 아예 못 한다. (참고로 이 시설의 GMP 방번호 자체가 3, 4층에만 부여돼 있어, 1, 2층에
  GMP 관리 대상 방이 없을 가능성도 있다. 이 점도 함께 확인 요청 - A-3 보충 참조.)
- **없으면 막히는 것**: 1, 2층 압력 검사.
- **A-3 보충(확인 요청)**: 1, 2층에 GMP 청정관리 대상 방이 존재하는가? (설계개요상 1층 공장/2층
  등으로 나오나, 방번호 체계가 3, 4층만이라 확인이 필요하다.)

### A-4. 도면 속 숫자(TA 레이어)의 단위 확정 - [중요]
- **무엇을**: 차압 도면의 특정 부분(TA 레이어)에 적힌 숫자 98개가 무엇을 뜻하는지 확정.
  값 범위는 대략 90~300이다.
- **왜 필요한지(상세)**: 이 숫자가 "방에 시간당 넣는 공기 양(급기량, 단위 CMH)"인지 "옆방과의
  기압 차이(차압, 단위 Pa)"인지에 따라 해석이 완전히 달라진다. 잘못 해석하면 압력 규칙 전체가
  오염된다.
- **없으면 막히는 것**: 이 숫자를 어떤 규칙에도 쓸 수 없다.
- **현재 임시 처리**: 값을 원본 그대로만 저장하고 어떤 규칙도 참조하지 않도록 막아 두었다(단위
  확정 전까지 사용 금지).

### A-5. 차압 화살표 방향의 "의미" 확정 - [긴급]
- **무엇을**: 차압 도면의 화살표(98개)가 가리키는 방향이 "고압 → 저압"을 뜻하는지, 아니면 반대인지.
- **왜 필요한지(상세)**: 우리가 화살표의 기하학적 방향(어느 쪽을 가리키는지)은 이미 정확히
  계산했다. 하지만 그 화살표가 "기압이 높은 방에서 낮은 방으로" 흐름을 뜻하는지, 반대를 뜻하는지는
  도면만으로 확정할 수 없다. 이 의미를 반대로 해석하면 가장 중요한 압력 규정 검사(제조실이 복도보다
  기압이 높아야 한다 등)가 정반대로 작동해, 정상인 도면을 위반으로, 위반을 정상으로 판정하게 된다.
- **없으면 막히는 것**: 압력 방향 규칙(PRES 계열)을 정식으로 못 켠다. 지금은 안전을 위해 일부러
  꺼 두었다.
- **확인 방법 제안**: 명백한 사례 2~3개(예: 제조실 → 복도 방향)로 대조하거나, 설계 기준서에서
  화살표 표기 규칙을 확인해 주면 된다.

### A-6. DWG 원본과 DXF의 정합 / 도면 개정 이력 - [운영]
- **무엇을**: 현재 우리가 쓰는 DXF가 어떤 도구로 변환됐는지, DWG 원본과 내용이 일치하는지,
  그리고 최신 개정본이 맞는지.
- **왜 필요한지(상세)**: 변환 과정에서 일부 정보(속성, 특수 객체)가 소실될 수 있고, 옛 도면 잔재가
  섞이면 "유령 방" 같은 오염이 생긴다. 최신 개정본 여부 확인은 검사 결과의 신뢰성과 직결된다.
- **부탁 형태**: DWG 원본 동봉(대조용) + 도면 개정 번호/일자 명시.

## B. 규정, 명명 규칙 (검사 정확도)

### B-1. GMP 규정 근거 조항 - 컨설턴트 검수 - [중요]
- **무엇을**: 우리가 만든 규정 위반 검사 규칙 하나하나가 실제 어느 규정(국내 고시 별표17, 국제기준
  PIC/S Annex 1, ISPE 가이드 등)의 어느 조항에 근거하는지, GMP 전문가(컨설턴트)의 검수, 확인.
- **왜 필요한지(상세)**: 검사 규칙이 법적 근거를 갖지 못하면 납품물로서 신뢰받기 어렵고, 근거가
  틀리면 잘못된 위반을 양산한다. 규칙의 정확성이 곧 납품 품질이다.
- **없으면 막히는 것**: 규칙을 "초안(draft)" 상태로만 둘 수 있고 정식 판정 근거로 쓰기 어렵다.
- **부탁 형태**: 규칙 목록을 전달할 테니 각 규칙에 대해 "맞음/수정 필요/근거 조항"을 표기.

### B-2. 방 이름 → 유형, 등급 매핑 확인 (애매한 이름들) - [중요]
- **무엇을**: 도면의 방 이름 중 자동으로 유형, 등급을 판정하기 애매한 것들의 확인. 예: 단순히 "방"
  으로만 적힌 것, "(N)" 접두(신축 표시로 추정), "A"/"B" 접미(구역 구분 추정), 괄호 안 번호
  "(3115)"(기존동 참조로 추정) 등.
- **왜 필요한지(상세)**: 검사, 추론이 방 이름에 의존하는 부분이 있는데, 이름이 애매하면 판정이
  흔들린다. 실제로 우리 검사에서 방번호 3117, 4107이 평면도엔 "방", 차압도엔 "PD/AV"로 서로 다르게
  적혀 불일치로 검출됐다. 이런 표기 차이가 오기(誤記)인지 의도된 것인지 확인이 필요하다.
- **부탁 형태**: 애매 사례 목록을 정리해 전달할 테니 표준 명칭/의미를 확인. 특히 괄호 번호
  "(3115)" 표기의 의미(기존동 참조 여부).

## C. 법률, 계약 (코드 작성보다 먼저 답이 필요) - [법률]

이 세 가지는 기술 문제가 아니라 프로젝트의 법적 안전과 직결된다. 특히 C-1, C-2는 AI 생성, 학습
단계(3~4단계)의 코드를 짜기 전에 반드시 서면으로 확인받아야 한다.

### C-1. 제공 도면의 저작권, AI 학습/변형 사용 범위 서면 확인 - [법률]
- **무엇을**: 발주처가 제공한 실도면을 (1) 배치안 생성의 참고(변형), (2) AI 모델 학습에 사용해도
  되는지, 그리고 그 권리 범위.
- **왜 필요한지(상세)**: 도면의 저작권은 원 설계사무소에 있을 가능성이 높다. 발주처가 소유권을
  가졌는지, "파생 설계 생성"이나 "AI 학습"에 쓸 권한이 사용 허락 범위에 포함되는지가 불명확하다.
  이를 확인하지 않고 학습, 변형에 쓰면 저작권 분쟁 위험이 있다.
- **확인 전 우리 대응**: 확인 전까지는 실도면의 기하 형태를 복제하지 않고 통계, 위상 정보만
  사용하며, 학습은 합성(가짜) 데이터 중심으로 진행한다.

### C-2. 외부 AI 서비스로의 도면 데이터 반출 가능 여부 - [법률]
- **무엇을**: 방 목록, 도면 요약 등을 외부 AI(예: Claude API 같은 클라우드 언어모델)로 전송해도
  되는지.
- **왜 필요한지(상세)**: 계약, 보안 규정에 "데이터 외부 반출 금지" 조항이 있으면, 도면 정보를
  외부 API로 보내는 순간 위반이 된다.
- **확인 전 우리 대응**: 확인 전까지 외부로 보내는 데이터는 익명화(방 이름을 코드로, 시설명 제거,
  좌표 정규화)해서만 전송하고, 전송 기록을 보관한다.

### C-3. 포트폴리오, 홍보 사용 허락 서면 합의 - [법률]
- **무엇을**: 본 프로젝트의 결과물(익명화된 리포트, 비교 이미지, 기술 설명)을 개발자 포트폴리오나
  기술 홍보에 사용해도 되는지, 그 공개 범위.
- **왜 필요한지(상세)**: 고객명, 실도면, 실제 방 이름 등 식별 정보는 전부 제거하더라도, 사후 분쟁을
  막으려면 공개 범위를 계약 초기에 서면으로 합의해 두는 것이 안전하다.
- **부탁 형태**: 공개 가능 범위(합성 데모/익명 지표/기술 글) 명시한 간단한 서면 합의.

## D. 운영, 향후 (효율, 견적)

### D-1. 향후 수령할 도면의 설계사 동일 여부 - [운영]
- **무엇을**: 앞으로 추가로 받을 시설 도면들이 같은 설계사무소에서 그린 것인지.
- **왜 필요한지(상세)**: 같은 설계사의 도면이면 레이어 이름, 표기 관례가 비슷해, 우리 "설정서
  (프로파일)" 재사용률이 높아 온보딩이 빠르고 저렴하다. 다르면 설정을 새로 잡아야 한다. 이는
  향후 작업 견적, 기간 산정에 반영된다.

### D-2. AutoCAD 실기 열람 테스트 환경 - [운영]
- **무엇을**: 우리가 뽑아낸 결과나 향후 생성할 도면을 실제 AutoCAD에서 열어 검수할 수 있는 환경/협조.
- **왜 필요한지(상세)**: 자동 추출, 생성 결과가 실제 CAD 프로그램에서 정상적으로 열리고 보이는지를
  사람이 최종 확인해야 신뢰할 수 있다.
