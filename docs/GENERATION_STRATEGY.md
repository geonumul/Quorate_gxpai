# GXPAI 생성(Generation) 정면돌파 작전 — 문헌 전수조사 기반 총력전 계획 v1.0
### "요구조건 → 규정 준수 도면 자동 생성"을 끝까지 미는 문서

> 결론 요약: 목표를 정확히 정의하면(개념설계 산출물 세트) 도달 가능하다.
> 무기는 6트랙 병렬 + 셀프플레이 데이터 플라이휠. 각 트랙은 실존 논문 계보 위에 선다.
> 이 문서는 가이드라인 v2의 Stage 3~4를 대체·확장한다.

# 0. 목표의 재정의 (가장 중요한 전략적 수정)

## 0.1 우리가 이기면 되는 게임
발주처의 목표도면(QUINTEX OSD Cleanliness Plan)과 소개서의 개념설계 산출물 18종을 분해하면:

| 개념설계 산출물 | 우리 온톨로지에서 도출 가능? | 근거 |
|---|---|---|
| 평면도(GMP Layout) | ◎ 생성 대상 그 자체 | 방 폴리곤 배치 |
| 청정도 구분도 | ◎ Grade 노드 → 색칠 | 그래프 속성 투영 |
| 실간 차압도 | ◎ PRESSURE_OVER 엣지 → 화살표 | 그래프 속성 투영 |
| 인동선/물동선/폐기물/검체/세척 동선 | ○ 복도 그래프 경로 | 경로 탐색 |
| AHU 조닝 | ○ SERVED_BY 클러스터 | 그래프 분할 |
| 공정흐름도 | ○ PlanSpec의 공정 시퀀스 | 입력 데이터 |
| 청정실 높이/디자인 요구 | △ 표 형태 산출 | 속성 테이블 |
| 기계설비설계, 시공도 | ✗ 스코프 밖 (컨설턴트/설계사무소 영역) | — |

**즉 18종 중 3분의 2가 "배치 그래프 하나를 여러 관점으로 투영한 것"이다.**
평면 배치 1개를 규정 준수로 생성하면 청정도도·차압도·동선도는 부산물로 따라 나온다.
"28장 세트"의 공포는 허상이고, 진짜 문제는 단 하나 — **규정 준수 배치 그래프의 생성**이다.

## 0.2 승리 조건 (측정 가능하게)
- G1: PlanSpec(방 목록+요구) 입력 → **critical violations 0건** 배치안 K개(K≥5) 산출, 10분 이내
- G2: 배치안에서 청정도도·차압도·동선도 자동 투영 출력 (DXF+SVG)
- G3: GxP 컨설턴트 블라인드 평가에서 "수정 후 사용 가능" 등급 ≥ 60% (초안으로서의 합격선)
- G4: 컨설턴트 수정량(이동·크기변경 방 수)이 버전이 거듭될수록 감소하는 추세 입증

# 1. 문헌 지도 — 누가 어디까지 왔나 (전수조사 결과)

## 1.1 그래프 조건부 신경 생성 계보 (우리 입력 형식과 정확히 일치)
- **House-GAN / House-GAN++** (Nauata et al., 2020/2021): 방 유형+인접 그래프 조건부 생성. 원조
- **Graph2Plan** (Hu et al., TOG 2020): 레이아웃 그래프 + 건물 외곽 조건 → 평면. 외곽 제약이 우리 케이스(기존 건물 리노베이션)와 직결
- **WallPlan** (Sun et al., TOG 2022): 벽 그래프를 직접 생성 — 방 박스가 아닌 벽 중심 표현
- **HouseDiffusion** (Shabani et al., CVPR 2023): 벡터 평면 디퓨전 (이산+연속 디노이징)
- **GSDiff / DiffPlanner** (2024/TVCG 2025): 기하 강화 구조 그래프 디퓨전, 래스터 제거 직접 벡터 생성
- **FloorplanMAE** (2025): 부분 입력 → 완성 (마스킹 자기지도) — "기존동 고정 + 증축부 생성" 시나리오에 유용
- **HypergraphFormer** (2025): LLM으로 요구사항 → 하이퍼그래프 → 편집 가능 평면
- **Edge-aware GNN + P-PLAN** (Applied Intelligence 2025): 주거가 아닌 **대형 공공건물** 레이아웃 + 정량 평가지표(접근성 지수 등) + 4,535장 데이터셋 — 비주거 확장의 선례
- **Constrained Layout Generation with Factor Graphs** (CVPR 2024): 팩터 그래프로 제약을 명시적 표현

## 1.2 LLM + 검증가능보상 (우리 아키텍처의 직접 근거)
- **Generative Floor Plan Design with LLMs via RL with Verifiable Rewards** (2026, arXiv 2605.14117):
  방 폴리곤을 JSON으로 인코딩 → LLM fine-tune → **규칙 체커를 보상으로 RL**. RPLAN 기반.
  → **우리 violations 엔진 = 이 논문의 verifiable reward**. 도메인만 GMP로 바꾸면 방법론 이식 가능
- **Prompts to Layouts: Hybrid GNN + agent-based model** (Automation in Construction 2025)
- **MedBuild AI** (2025, arXiv 2511.11587): LLM에 병원 레이아웃 유형 라이브러리(typology library)를
  지식 주입 — 검증된 아키타입 안에서만 생성하게 제약. **우리 레퍼런스 온톨로지 = GMP 유형 라이브러리**

## 1.3 병원 = GMP의 자매 도메인 (규제·오염·동선이 동형)
- **Architectural spatial layout design for hospitals: A review** (Journal of Building Engineering 2024):
  HSLP+유전알고리즘, pix2pix GAN, **인접 선호점수 + 감염위험계수** 파라미터화 생성 —
  감염위험계수 ≡ 교차오염계수로 치환하면 GMP 목적함수의 설계도
- **ED 레이아웃 GAN** (2021), 육각 셀룰러 오토마타 절차적 생성 (인접+면적+경계 만족, 소데이터에서 작동)
- **MCTS로 직사각 평면 인접 제약 해결** (Shi et al., Automation in Construction 2020)

## 1.4 OR/제약 풀이 최신
- **하이브리드 CDCL + CP-SAT for FLP** (2025, arXiv 2512.18034): 인접 요구/분리 금지/통로/다층 —
  GMP 제약 어휘와 1:1. OR-Tools CP-SAT가 이미 우리 스택
- **다열 FLP MILP** (Optimization Letters): 정확해는 ~13개 부서 한계 → 대형 인스턴스는 2단계 분해.
  우리도 층/존 단위 분해가 필수라는 근거
- **KG-RAG로 FLP 알고리즘 선택** (2025): 문제 특성 → 적합 알고리즘 추천. 우리 다중 트랙 라우팅에 참고

## 1.5 냉정한 갭 확인
GMP 클린룸 도면의 신경 생성 논문은 **없다** (2026-07 기준 검색 범위 내). 데이터셋도 없다.
= 리스크이자, 이 프로젝트가 학술 기여(논문)까지 될 수 있는 기회. 갭은 데이터이지 방법이 아니다.

# 2. 6트랙 총력전 아키텍처

핵심 사상: **단일 생성기를 믿지 않는다. 생성기 군단 + 완벽한 심판(violations 엔진) + 수리공(repair).**

```
PlanSpec ─┬─ Track A: CP-SAT/MILP 정통 제약 풀이 ──┐
          ├─ Track B: 레퍼런스 검색·변형(CBR) ──────┤
          ├─ Track C: 신경 생성(디퓨전/GNN) ────────┼─→ 후보 풀(수십~수백)
          ├─ Track D: LLM+RLVR ────────────────────┤        │
          └─ Track E: MCTS/RL 탐색 ────────────────┘        ▼
                                          [심판] violations 엔진 (hard 필터)
                                                            │
                                          [수리공] Track F: CP-SAT repair
                                                            │
                                          [랭킹] soft 점수(동선 길이, 면적 적합, 레퍼런스 유사도)
                                                            │
                                              상위 K개 → 투영(청정도도/차압도/동선도) → DXF
```

## Track A — 제약 풀이 (기반, 반드시 작동해야 하는 층)
- CP-SAT: 방=가변 직사각형(x,y,w,h 정수변수), no-overlap 전역제약, 인접 요구=경계 공유 길이 ≥ 문폭,
  분리 금지, 갱의 체인=경로 존재, 존 묶음, 외곽 고정(리노베이션)
- 스케일 한계 대응(문헌 1.4 근거): **위계 분해** — (1) 존 레벨 배치(존 6~8개) → (2) 존 내부 방 배치
  (방 10~20개/존) → (3) 경계 조정. 각 단계는 CP-SAT 감당 범위
- infeasible 진단 모드(가이드라인 R-E5) + 제약 완화 사다리(hard→soft 강등 순서 명시)
- 산출: "규정상 가능함이 증명된" 해. 예쁘진 않아도 **합법성 보증** — Track C/D의 학습 데이터 공장이기도 함

## Track B — 레퍼런스 검색·변형 (Case-Based Reasoning, 실무자 모사)
- 온톨로지에 쌓인 기존 도면들에서 PlanSpec과 가장 가까운 사례를 그래프 유사도로 검색
  (LayoutGKN 류 graph similarity, 또는 graph edit distance)
- 검색된 사례의 위상(존 순서, 갱의 체인 구조)을 뼈대로 고정, 방 크기·개수만 재최적화(CP-SAT 부분 문제)
- MedBuild AI의 typology library 사상 — 단, 라이브러리가 프롬프트가 아니라 **실측 온톨로지**라 더 강함
- N=1인 지금도 작동한다 (내용고형제 1건 = 아키타입 1개). 시설이 쌓일수록 지수적으로 좋아지는 트랙

## Track C — 신경 생성 (디퓨전/GNN) [데이터 플라이휠 가동 후]
- 표현: HouseDiffusion/GSDiff 계열 벡터 표현 채택 (래스터 금지 — DXF 직결)
- **학습 데이터 = Track A가 만든 합성 정답**: CP-SAT로 PlanSpec 랜덤 샘플링 × 유효 배치
  수천~수만 개 생성. 실데이터(레퍼런스)는 fine-tune/스타일 앵커로
- 조건: 인접 그래프 + Grade + 외곽 폴리곤 (Graph2Plan 조건부와 동일 인터페이스)
- 기대 역할: Track A가 못 내는 "자연스러움·다양성" 담당. G3(컨설턴트 평가) 점수를 올리는 트랙

## Track D — LLM + 검증가능보상 (2026 RLVR 논문 직접 이식)
- 방 폴리곤 JSON 표현 (논문과 동일 포맷 사상) — 우리 master 스키마가 이미 이 형태
- 1단계(학습 없이): 프롬프트에 PlanSpec + 레퍼런스 요약 + 규칙 명세 → 후보 JSON 생성 →
  violations 엔진 피드백을 넣어 self-refine 루프 (지금 당장 가동 가능, API만으로)
- 2단계(플라이휠 후): Track A 합성 데이터로 SFT → violations 점수를 보상으로 GRPO/DPO
- **violations 엔진의 품질 = 이 트랙의 상한.** 심층검증 80항목이 곧 보상 함수의 신뢰도다

## Track E — 탐색 (MCTS/RL) [보조]
- 방을 하나씩 놓는 순차 결정 문제로 정식화 (Shi et al. MCTS 선례, RLDesigner 계열)
- 부분 배치 상태에서 violations 부분 평가가 가능해야 함 → 엔진에 incremental check API 추가
- 우선순위 낮음: A~D가 막힐 때의 예비 전력. 단 "기존동 일부 고정 + 증축부 배치" 같은
  부분 문제에서 의외로 강할 수 있음 (FloorplanMAE의 부분입력 사상과 결합)

## Track F — 수리공 (Repair) [승부처]
- 어떤 트랙의 후보든 minor 위반이 있으면 버리지 말고 고친다: 위반 엣지들을 제약으로 추가한
  **국소 CP-SAT 재풀이** (위반 관련 방 ±이웃만 변수로, 나머지 고정)
- "생성은 관대하게, 수리는 엄격하게" — 후보 풀의 실효 수율을 몇 배로 올리는 장치
- LLM 기반 수리(위반 설명 → 수정 JSON)와 CP-SAT 수리의 성능 비교 자체가 논문 소재

# 3. 데이터 플라이휠 — N=1 문제의 정면 돌파

```
[레퍼런스 실도면] ──온톨로지화──→ 아키타입·통계 priors (Track B, 목적함수)
        │
[Track A CP-SAT] ──대량 합성──→ 유효 배치 수만 개 (Track C/D 학습셋)   ← 셀프플레이 원리:
        │                                                              심판이 완벽하면
[Track C/D 생성물] ──심판 필터──→ 고품질만 재학습 (반복 증류)            데이터는 무한하다
        │
[컨설턴트 수정 DXF] ──diff 추출──→ 선호쌍(수정 전/후) → DPO·priors 갱신 ← 계획서의
        │                                                              "건수 누적 시 향상"의
[신규 시설 수령] ──파이프라인──→ 아키타입 추가, 전 트랙 동시 강화        실제 메커니즘
```

- **합성 데이터의 함정 경계**: CP-SAT 합성물은 "합법이지만 어색"할 수 있다 → 실도면 통계
  (방 크기 분포, 존 형상비, 복도 폭)를 합성 샘플러의 사전분포로 주입해 분포를 실도면 쪽으로 당긴다
- **컨설턴트 수정 diff가 최고 등급 데이터다**: 수정 전후 그래프 차이 = "전문가가 무엇을 못 참는가"의
  직접 신호. DB의 violation.status / review_status 컬럼(가이드라인 B.4)이 이걸 받는 그릇

# 4. 실행 계획 (Stage 3~4 대체)

## Wave 1 (납품 범위 내, +2주): A + B + D(1단계) + F
- W1.1 CP-SAT 위계분해 배치기 (존→방) + infeasible 진단 + 완화 사다리
- W1.2 레퍼런스 아키타입 추출기 (내용고형제 → 존 순서/갱의 체인/인접 통계)
- W1.3 LLM self-refine 루프 (API, 학습 없음): 생성→검증→피드백→재생성 ≤5회
- W1.4 repair 연산자 (국소 재풀이)
- W1.5 투영기: 배치 그래프 → 청정도도/차압도/동선도 SVG+DXF
- 게이트: G1(critical 0, K≥5, 10분) + G2 달성 → **이것만으로 발주처 시연 가능**

## Wave 2 (+3~4주): 플라이휠 점화 + C·D(2단계)
- W2.1 합성 데이터 공장 (PlanSpec 샘플러 + CP-SAT 대량 생산, 목표 1만 배치)
- W2.2 벡터 디퓨전 or LLM-SFT 중 택1 학습 (GPU: 계획서상 AWS Spot 활용 근거 있음)
- W2.3 RLVR: violations 점수 보상 GRPO (2026 논문 재현 → GMP 도메인 전이)
- W2.4 G3 블라인드 평가 프로토콜 (컨설턴트 3인, 실도면 vs 생성안 섞어 제시)
- 게이트: G3 ≥ 60%

## Wave 3 (지속): 자기 개선 운영
- 컨설턴트 diff 수집 자동화 → 분기별 priors/모델 갱신 → G4 추세 리포트
- 신규 시설마다: 온보딩(0줄) → 아키타입 자동 추가 → 전 트랙 즉시 수혜

# 5. 정직한 리스크 대장 (총력전이어도 눈은 뜨고 간다)

| 리스크 | 확률 | 대응 |
|---|---|---|
| CP-SAT이 실규모(방 60+/층)에서 timeout | 중 | 위계분해가 1차 방어, 존 경계 고정 2차, 그리드 조대화 3차 |
| 합성 데이터가 어색해 신경 생성 품질 정체 | 중 | 실도면 사전분포 주입 + Track B가 품질 바닥을 받침 |
| 컨설턴트 평가 60% 미달 | 중 | Wave 1 산출은 여전히 유효(초안+검증). G3는 반복 개선 지표로 전환 |
| RLVR 재현 실패(리소스/불안정) | 중 | Track D 1단계(self-refine)만으로도 차별화 성립. 2단계는 논문 트랙으로 이관 |
| 규칙 엔진 오류가 보상 오염 | 낮~중 | 심층검증 80항목이 이 리스크의 방어선 — 검증 문서가 생성의 기초공사인 이유 |
| 진짜 불가능 잔여물(시공도·MEP) | 확정 | 스코프에서 명시 제외(0.1 표). 약속하지 않은 것은 실패가 아니다 |

> 마지막 문장: "해결 못 한다"가 아니라 "해결의 정의를 이기는 게임으로 고정하고,
> 그 게임은 6트랙 전부로 친다"가 이 문서의 입장이다. 심판(검증 엔진)을 먼저 완성하라 —
> 심판이 완벽한 순간, 생성은 시간 문제가 된다.
