# GXPAI 프로젝트 마스터플랜 (전체 계획, 기술스택, 발주처 요청)

GMP(제약) 시설 도면 자동화 엔진의 전체 그림을 한 곳에 정리한다. 세부 문서는 각 절에서 링크한다.
(작성 원칙: 이 문서 및 모든 메모리, 문서는 한글. 사소한 것까지 전수 의심, 검수.)

---

## 1. 프로젝트 개요

- **무엇**: 제약(GMP) 시설의 CAD 도면(DXF/DWG)을 **읽어→구조화→규정 위반 검사→(미래)배치, 상세도 생성**하는 엔진.
- **왜**: (1) 발주 용역 납품물, (2) 본인(geonumul) 포트폴리오, 연구.
- **최종 지향**: AI가 상세시공도 수준까지 생성 → 자동 규정검토 → **사람은 최종 이상 유무 확인 + 날인만**(사람 개입 최소화).
- **저장소**: `gxpai-engine/` (private, main). 고객 원본 도면은 git 밖(커밋 금지).

---

## 2. 전체 로드맵 (5단계 + 미래 확장)

| 단계 | 이름 | 핵심 | 상태 |
|---|---|---|---|
| **1** | 읽기 (Ingestion) | 도면 → 방, 기압, 장비, 설계개요 추출, DB 적재 | **완료** |
| **2** | 검사 (Compliance) | 규정 위반 검출 + 감사등급 리포트 (필수 납품) | **진행 중** (뼈대, 하드닝 완료, 핵심규칙 데이터 대기) |
| **3** | 생성 (Generation) | 요구조건 → 규정 지키는 배치 자동 생성 → 청정도도, 차압도, 동선도 투영 | 예정 (논문, 작전 완료) |
| **4** | 지능화 (Intelligence) | 요구서 문서를 LLM이 읽어 입력 변환, 수정이력 학습 | 예정 |
| **5** | 서비스 (Service) | 위 기능을 웹 API 로 제공 | 예정 (CLI가 전신) |
| **미래** | 상세도 자동생성 | 발주처 설계사무소 kit(레이어, 블록 표준) 재사용 + 배치생성 + 자동 상세화 | 후속 (데이터 확보 후) |

계약 납품선 = **Stage 2 완성 + Stage 3 best-effort**. 4, 5, 미래는 후속.

| 영역 | 기술 | 용도 |

## 4. 아키텍처 원칙 (설계 철학)

1. **프로파일 기반** - 레이어명, 번호패턴, 규칙을 `profiles/*.yaml`, `rules/*.yaml`에 둔다. 신규 시설/사무소는
   프로파일만 등록 → **코드 수정 0줄 온보딩**. (사무소마다 CAD 표준이 다르므로 프로파일로 적응.)
2. **규칙 = 데이터, 실행 = 결정론 코드** - 규칙은 YAML(+ RASE 4연산자 근거추적), 검사는 `checks/<rule>.py`.
   LLM 은 규칙 해석, 초안, 리포트 서술에만, **판정은 결정론 코드**(감사 가능, 환각 차단).
3. **다중 시설 격리** - 모든 데이터는 `facility_id` 로 격리(결정론적 파생 id).
4. **감사추적(audit trail)** - run 은 append-only 불변 이력. 실패도 'failed'+error 로 남김. 위반마다 근거조항.
5. **정직성, 게이트** - 미확정 추정은 보류. 미검수 규칙은 게이트(enabled:false)로 잠금(GEN-R2).
6. **검증 우선** - 카나리아(111방, 3F51/4F60, LBL 3, 17) 불변 확인, 전수 적대적 리뷰, 다중 스케일 대조.
7. **IP 3-리포 분리** - 납품(gxpai-engine) / 개인소유 도메인중립(placement-core) / 확장(quorate-adapter).
   데이터 방화벽: 발주처 도면 파생물은 gxpai-engine 내부만. (docs 참조: 아래 9절)

## 5. 단계별 상세 계획

### Stage 1 - 읽기 (완료)
- `facility add`(zip/폴더 등록, 지문, 종류판별) → `ingest`(추출기: floorplan, pressure, hvac, equipment, overview, grades) → `_merge`(방번호 키 병합) → DB 적재.
- 추출: 번호방 111(3F51/4F60=기준), 무번호 52, 장비 418(귀속376), AHU 20, 설계개요 9, 화살표 98, TA 98.
- 리스크 반영: 글자정규화(R-A1), TEXT+MTEXT(R-A2), 여러줄병합(S-3), frozen제외(S-10), 정렬점(R-F1), 멱등(R-E3).

### Stage 2 - 검사 (진행 중, 필수 납품)
- **동작**: 규칙엔진(YAML→checks 동적실행→위반 적재), Neo4j 온톨로지, HTML 감사리포트, `run all` E2E.
- **규칙 상태**: LBL-001(이름불일치 3), LBL-002(도면간 방차이 17) **활성**. PRES-001(압력역전), ADJ-001(등급인접금지)
  **게이트 잠금**(발주처 확인, 검수 전). PRES-002, ADJ-002 미구현.
- **근거추적(RASE)**: 규칙마다 requirement/applicability/selection/exception + 근거조항 + 검수상태(review).
- **감사리포트**: 위반+근거조항 + "발주처 확인 대기" 섹션(잠긴 규칙, 미결 질문).
- **화살표↔방 귀속**: 관찰된 기하(head/tail)만 저장, 고압/저압 해석은 발주처 확인 전 NULL 유지.
- **남은 것**: 방 경계, 면적(엔지니어링 과제, 데이터 대기 아님), PRES/ADJ 활성(발주처 확인 후), 규칙 확장.

### Stage 3 - 생성 (예정, 6트랙 총력전)
- 사상: 단일 생성기 불신 → **생성기 군단 + 완벽한 심판(규칙엔진=검증가능보상) + 수리공(국소 repair)**.
- Track A(CP-SAT 제약풀이, 기반), B(레퍼런스 검색, 변형 CBR), C(신경 디퓨전/GNN), D(LLM+RLVR), E(MCTS), F(repair).
- 데이터 플라이휠: CP-SAT가 합성 정답 대량생산 → 신경/LLM 학습셋 → 심판 필터 → 반복 증류(N=1 정면돌파).
- 산출: 배치 그래프 1개 → 청정도도, 차압도, 동선도 **투영**(18종 중 3분의 2가 한 그래프의 투영).
- 승리조건: critical 위반 0 배치 K개(10분내), 컨설턴트 블라인드 "수정 후 사용가능" ≥60%.
- 상세: `30_생성단계_설계/GXPAI_생성_정면돌파_작전_v1.md`, `..._검증총람_PART1-15.md`(레드팀=PART11~15), `docs/42_논문_정독노트.md`.

### Stage 4 - 지능화 (예정)
- LLM 이 요구서 문서(공정, 실목록, 요구조건)를 읽어 생성 입력(PlanSpec)으로 변환.
- 컨설턴트 수정이력(before/after diff)을 선호학습(DPO), priors 로 흡수 → 사람 개입 축소.
- pgvector 임베딩, RAG(규정 검색).

### Stage 5 - 서비스 (예정)
- **FastAPI** 로 core 함수를 API 화. cli.py가 얇은 래퍼라 껍데기만 추가(API_CONTRACT).

### 미래 - 상세도 자동생성
- 발주처 설계사무소의 **CAD 표준(레이어)+블록 라이브러리** 재사용 → 배치 생성 → **그들 블록을 규칙대로 조립, 투영**
  → 상세가 실제와 동일. + 자동 규정검토 → 사람 최종 체크+날인. (손코딩 프리핸드 모사가 아니라 kit 조립.)

## 7. 발주처 요청사항 (전부, 빠짐없이)

상세, 전달용: `docs/22_발주처_데이터요청_통합.md`. 여기선 요약.

### A. 지금 필요 (검사기 활성화 = 현 납품물 완성)
1. **청정등급(Grade) 도면** - 방별 A/B/C/D. 현재 전부 비어 있음 → 등급 인접(ADJ) 규칙 전부 막힘. 최우선
2. **화살표 의미 1줄 확인** - "차압 화살촉은 저압 쪽을 가리키는 게 맞나요?" → PRES-001 활성.
3. **TA 단위 확인 + 실제 차압(Pa) 수치 위치** - TA는 풍량(CMH)로 추정, 차압 아님. PRES-002용 실제 Pa 소재.
4. **1, 2층 차압 도면** - 현재 3, 4층만. 해당 층 압력검사 불가.
5. **GMP 컨설턴트 검수** - 규칙 근거조항, 등급서열(grade_rank), 금지인접쌍, 기준차압값(전부 검수대기).
6. **원본 DWG** - 변환 DXF는 좌표계, 블록 깨짐. (XREF는 이미 bound라 벽기하는 확보됨 → XREF 원본은 선택.)
7. **도면 라벨 ↔ 규제 용어 매핑** - "탈의실=어느 등급 전이", "전실=에어락" 등.

### B. 후속 (상세도 생성 학습용)
8. **여러 프로젝트 전체 도면 세트(원본 DWG)** + XREF 소스 - 학습 본체.
9. **CAD 표준(그 사무소 것)** - 레이어, 선유형, 펜위계, 문자스타일. (사무소마다 다름 → 프로파일로 적응.)
10. **블록/심볼 라이브러리(.dwg)** - 문, 창, 기구, HVAC, 기둥, 계단. **상세가 실제와 동일해지는 열쇠.**
11. **표준 상세도(디테일 라이브러리)** - 벽단면, 패널조인트, 문/창호, 바닥/천장.
12. **표제란(도면 양식) 템플릿**.
13. **요구조건↔도면 쌍** - 실목록, 면적표, 실별 데이터시트(등급, 차압, 환기, 마감), 공정흐름도, 장비리스트.
14. **도면 수정 이력(before/after) + 검토의견 + 준공도(as-built)** - 사람 개입 축소 학습의 최고급 재료.
15. **적용 규정 목록, 해석 + GMP 검수 기준** - 자동 규정검토 근거.

### C. 법률, 보안 (코드보다 먼저)
16. **AI 학습, 파생생성 사용 동의(서면)** - 도면 저작권(원 설계사무소 가능성).
17. **데이터 반출/클라우드 학습 가능 여부** - 외부 API, GPU 학습 시 반출 조항.

### 강조 3가지
- **PDF 말고 원본 DWG**(+블록, XREF). / **CAD 표준, 블록 라이브러리**(똑같은 상세의 열쇠). / **수정 이력**(개입 축소).
