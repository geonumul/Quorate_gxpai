# PART 5. DXF/CAD 포렌식 — 파일 자체를 의심하라

**R-F1. TEXT 정렬점 버그 [필수] ★현재 코드에 잠복 중인 버그 가능성 최고**
`e.dxf.insert`는 halign/valign이 0(LEFT/BASELINE)일 때만 텍스트 위치다. 중앙정렬/우측정렬
텍스트는 `align_point`가 진짜 위치이고 insert는 쓰레기 값일 수 있다. 설계사가 방이름을
중앙정렬로 찍었으면 **현재 파서의 좌표가 전부 몇 미터씩 어긋나 있을 수 있다.**
→ 검증: 전 TEXT의 halign/valign 분포를 inventory에 추가. 0이 아닌 비율 확인.
→ 수정: `ezdxf.tools.text.TextLine` 또는 `e.get_placement()` 사용으로 통일. 지금 즉시.

**R-F2. OCS/extrusion 미러 [필수]**
extrusion vector가 (0,0,-1)인 엔티티는 미러 좌표계(OCS)에 있다 — 좌표를 그대로 읽으면
x가 반전된 위치다. 복사-미러로 그린 도면에서 흔하다.
→ 검증: `e.dxf.extrusion != (0,0,1)` 엔티티 수를 inventory에. 존재 시 `ezdxf.math.OCS`로 WCS 변환 강제.

**R-F3. Z좌표 오염 (3D 찌꺼기) [필수]**
2D 도면인데 TEXT/LINE의 z≠0인 경우(3D 모델에서 투영, 실수로 elevation) — 거리 계산에
z가 섞이면 매칭 거리 폭발. → 전 좌표 z 분포 확인, 파서는 xy만 사용하도록 명시 + z≠0 비율 지표화.

**R-F4. 점선 = 철거선/상부오픈 [필수]**
linetype이 DASHED/HIDDEN인 벽은 철거벽·가벽·상부 오픈 표기다. 이걸 벽으로 취급하면
**철거된 방이 살아나고, 없는 벽으로 방이 쪼개진다.** 증축 도면(우리 데이터가 정확히 이것)에서 치명적.
→ 검증: 벽 레이어의 linetype 분포. 프로파일에 `wall_linetypes_include: [Continuous, ByLayer(연속인 경우)]`.
레이어명 `*HID*`, `*DASH*`, `*철거*`, `*EXST*` 는 별도 태깅.

**R-F5. 겹쳐 찍은 중복 텍스트 [권장]**
같은 자리에 같은 TEXT를 2번 찍는 관행(볼드 효과)이 있다 → 방 라벨 중복 카운트, 병합 로직 교란.
→ 좌표+내용 동일(허용오차 10mm) 중복 제거를 정규화 단계에 추가. 중복률 지표화.

**R-F6. DIMENSION/LEADER 내부 텍스트 오염 [필수]**
치수선(DIMENSION) 안의 측정값 텍스트, 지시선(LEADER/MLEADER) 텍스트가 TEXT 순회에 섞이면
숫자 라벨("3600")이 방번호 후보로 오인될 수 있다.
→ 부모 엔티티 타입 필터. 4자리 숫자 방번호 정규식이 치수값과 충돌하는지 층별로 점검.

**R-F7. 대좌표 정밀도 붕괴 [권장]**
국가좌표계(EPSG) 기반 도면은 좌표가 수백만 단위 — float 연산·shapely 정밀도 저하, 미세 슬리버 양산.
→ 검증: bbox 원점 거리 확인. 100만 초과 시 시설 로컬 원점으로 평행이동 후 처리(역변환 행렬 보관).

**R-F8. 헤더 vs 실제 불일치 [편집증]**
`$EXTMIN/$EXTMAX`(도면 범위)와 실제 엔티티 bbox가 크게 다르면 = 잔재 엔티티가 멀리 떨어져 존재
(우주 미아 엔티티). 이 미아들이 최근접 매칭을 오염시킨다.
→ 실bbox의 99.9 percentile 밖 엔티티를 격리 목록으로. `$INSUNITS`, `$MEASUREMENT`, `$LUNITS` 기록.

**R-F9. 뷰포트 동결(VP freeze)·투명도·비가시 [편집증]**
레이어가 전역 on이어도 특정 뷰포트에서 frozen일 수 있고, 색 255/투명 엔티티는 출력물엔 없지만
데이터엔 있다. PDF와 DXF의 "보이는 것" 차이의 주범.
→ X-8(PDF 대조)에서 불일치 발생 시 첫 용의자로 조사하는 절차만 문서화.

**R-F10. 곡선벽 (ARC/SPLINE/ELLIPSE) [권장]**
flood-fill이 LINE만 union하면 곡선벽 구간이 뚫린다.
→ 벽 수집 시 ARC는 세그먼트화(flattening, sagitta 5mm), SPLINE은 `.flattening()`. 벽 레이어의
엔티티 타입 분포를 inventory에 — LINE 외 비율이 있으면 반드시 처리.

**R-F11. 주석 축척(annotative) 텍스트 [편집증]**
annotative 텍스트는 높이가 컨텍스트 의존 — median_text_height 캘리브레이션(4.2)이 왜곡될 수 있다.
→ height=0 또는 스타일 참조 높이인 텍스트 비율 확인, 캘리브레이션에서 제외.

**R-F12. 유니코드 이스케이프 [권장]**
`\U+xxxx` 형식 문자가 raw로 남는 경우(변환기 산물). 이름 매칭 실패 원인.
→ normalize_dxf_text에 `\U+` 디코딩 포함.

**R-F13. XREF 중첩·순환 [편집증]**
XREF가 XREF를 참조(중첩), 심하면 순환. 원본 수령 시 resolve 순서 문제.
→ 수령 시 `doc.blocks`에서 xref 플래그 블록 목록화, 중첩 깊이 기록. resolve는 ODA로 bind 요청이 최선.

# PART 6. 기하 심층 — 폴리곤을 의심하라

**R-G1. 방 폴리곤 상호 겹침 = 0 검증 [필수] ★총람에 빠져 있던 핵심 불변량**
모든 방 폴리곤 쌍의 교집합 면적은 0이어야 한다(벽 두께만큼 떨어져 있어야 정상).
겹침 > 0.1㎡ = boundary 추출 오류의 확정 신호. X-25로 등록: pairwise overlap matrix, 위반 쌍 목록.

**R-G2. 커버리지 갭 검증 [필수]**
층 외곽 폴리곤 면적 = Σ(방) + 벽체 + 샤프트 + 미추출분. 잔차(외곽 − Σ방 − 벽추정)가
크면 = 못 잡은 방이 있다는 뜻. **"몇 개를 놓쳤는지 모른다"를 "몇 ㎡를 놓쳤는지 안다"로 바꾸는 검증.**
X-26: 층별 커버리지율 리포트 (목표 85%+, 잔차 위치를 SVG에 회색 표시).

**R-G3. self-intersection / 방향성 [필수]**
flood-fill 산출 폴리곤의 `is_valid` 전수 검사. invalid → `buffer(0)` 정화 → 그래도 invalid면 격리.
CW/CCW 방향에 따라 면적 부호가 뒤집히는 자체 구현 금지 — shapely `.area`만 사용 (abs 금지: 부호가
음수면 버그를 숨기지 말고 터뜨릴 것).

**R-G4. 좌표 스냅핑 [권장]**
12345.0000001 같은 부동소수 찌꺼기 → union 슬리버의 근원. 벽 수집 직후 1mm 그리드 스냅
(`round(x)`) 후 기하 연산. 스냅 전후 결과 차이를 1회 측정해 안전성 확인.

**R-G5. ㄱ자·도넛 방, 초박형 복도 [권장]**
방이 MultiPolygon으로 나오면(기둥이 방을 관통해 분할) 최대 조각만 취하지 말고 라벨 포함 조각 선택.
최소 폭 검증: `polygon.buffer(-450).is_empty` 인 "방"은 폭 900mm 미만 = 방이 아니라 벽 사이 틈일
가능성 → 격리.

**R-G6. 층간 수직 정합 검증 [권장] ★강력 추천**
계단실·EPS/TPS·PD/AV·엘리베이터는 **모든 층에서 같은 평면 위치**여야 한다.
시트 원점 보정(시트 앵커 기준 상대좌표) 후 3F 계단실 폴리곤과 4F 계단실 폴리곤의 IoU ≥ 0.7 검증.
어긋나면 = 시트 정렬 오류 or 추출 오류. X-27로 등록. 층간 정합은 사람도 놓치는 오류를 잡는다.

**R-G7. 기둥 그리드 기반 좌표계 검증 [편집증]**
도면의 X1~Xn/Y1~Yn 기둥 그리드(bubble 레이어 129개 텍스트가 이것일 가능성)를 추출하면:
(a) 그리드 간격의 규칙성으로 축척 재확인, (b) 시트 간 그리드 정렬로 R-G6의 원점 보정 자동화,
(c) 설계개요의 기둥 스팬 값과 대조. bubble 레이어 조사 태스크로 등록.

**R-G8. 인접의 대칭성·자기참조 [필수]**
adjacency(A,B) ⇒ adjacency(B,A) 확인, A=A 자기 엣지 금지, 같은 쌍 중복 금지. DB 제약으로 강제
(`CHECK (room_a < room_b)` 정렬 저장).

# PART 7. GMP 도메인 심층 — 규정 관점의 추가 검증·규칙 후보

> Grade/추가 도면 수령 후 순차 활성화. 규칙 YAML에 미리 draft로 넣고 `enabled: false`.

**X-28. 차압 최소값 [필수, 데이터 수령 후]**: 인접 등급 경계 차압 ≥ 10~15Pa (PIC/S 권고).
TA 단위 확정 + Grade 확보 시 활성화.

**X-29. 에어락 타입 판정 [권장]**: 에어락(전실) 양측 화살표 패턴으로 cascade/bubble/sink 분류 →
용도(인동선 PAL vs 물동선 MAL)와 어울리는지. 이름 사전에 PAL/MAL/전실 구분 추가.

**X-30. 갱의 단계 수 vs 등급 [권장]**: D급 진입 = 1차 갱의, C급 = 2차 갱의 체인 길이 검증.
그래프 최단경로 길이로 판정.

**X-31. 인동선-물동선 교차 [편집증→Stage 3에서 필수]**: 복도 그래프에서 인원 경로와 자재 경로의
엣지 공유 검출. 컨셉도면 PDF의 동선도(Personnel/Material Flows)를 골드 기준으로 대조 가능.

**X-32. 비상탈출 도달성 [권장]**: 모든 방에서 계단실까지 그래프 경로 존재 + 홉 수 상한.
violations이라기보다 그래프 완결성 검증을 겸한다(경로 없음 = 인접 누락 신호).

**X-33. 천장고 교차검증 [편집증]**: 단면도(A-401~406, 아직 미파싱)에서 층고·천장고 추출 →
컨셉도면의 Room Height 요구와 대조. 단면도 파서는 Stage 4 백로그.

**X-34. 외벽 접촉 제조실 [편집증]**: Grade B/C 제조실이 외벽·창에 직접 접하면 검토 플래그
(단열·결로·기밀 이슈). 외곽 폴리곤과의 경계 공유로 판정.

**X-35. 회수공기 조닝 [편집증]**: 서로 다른 제품 접촉 구역이 같은 AHU 리턴을 공유하는지
(교차오염 경로). HVAC 존 데이터 확보 시.

# PART 8. 통계·섭동 기반 검증 — 결과의 안정성을 의심하라

**X-36. 임계값 민감도 분석 [권장] ★confidence의 실증적 기반**
모든 임계값(k배율)을 ±20% 흔들어 파이프라인 재실행 → 결과가 바뀌는 방 목록 = "임계값 경계에
걸친 위태로운 레코드". 이 방들의 confidence를 자동 하향. `gxpai verify --sensitivity` 커맨드.
결과가 임계값에 둔감하다는 것을 보여주는 그래프 = 포트폴리오 최상급 소재.

**X-37. 좌표 섭동 테스트 [편집증]**
전 좌표에 ±30mm 노이즈 주입 후 재실행 → 방 매칭·인접이 몇 % 유지되는가(안정성 점수).
로버스트하지 않은 알고리즘을 조기에 드러낸다.

**X-38. 분포 기반 이상 감지 [권장]**
방 타입별 면적 분포(로그정규 가정) 적합 → 마할라노비스 거리 상위 플래그. 라벨 좌표 밀도
클러스터링(DBSCAN)으로 "라벨이 비정상적으로 몰린 곳"(중복 찍기, 범례 오인) 감지.

**X-39. 이중 구현 대조 (N-version) [권장]**
면적·인접 같은 핵심 계산을 독립 구현 2개로: shapely `.area` vs 자체 shoelace 공식,
buffer-교차 인접 vs 최근접 경계거리 인접. 불일치 = 버그 신호. 핵심 함수 3개만 적용해도 값어치 충분.

**X-40. 규칙 상호 모순 검사 [편집증]**
규칙 세트가 커지면 서로 모순되는 판정(한 규칙은 인접 요구, 다른 규칙은 인접 금지)이 생긴다.
합성 도면 생성기로 랜덤 배치 1,000개를 만들어 전 규칙 실행 → 동시에 위반 불가능한 규칙쌍 탐지.

# PART 9. 소프트웨어 신뢰성 — 코드 자체를 의심하라

**R-H1. 비결정성 사냥 [필수]**
같은 입력 → 같은 출력을 깨는 것들: set/dict 순회 순서에 의존한 매칭(동률일 때 승자가 바뀜),
float 합산 순서, 랜덤 시드 미고정(CSP), 병렬 처리 순서. 
→ 동률 처리에 명시적 tie-breaker(좌표 사전순), 전 랜덤 시드 고정, CI에 2회 실행 해시 비교(X-20 승계).

**R-H2. property-based testing [권장]**
hypothesis로 기하 함수 불변량 테스트: "임의 직사각형 방 배치에서 인접은 대칭", "폴리곤 평행이동에
면적 불변", "정규화 함수는 멱등(f(f(x))=f(x))". 손으로 못 만드는 엣지케이스를 기계가 찾는다.

**R-H3. mutation testing [편집증]**
mutmut로 소스에 인위 버그 주입 → 테스트가 잡는지. "커버리지 80%"가 허수인지 실질인지 판별.
compliance/checks만이라도 적용 — 규칙 코드의 테스트 품질이 납품 품질이다.

**R-H4. 손상 입력 퍼징 [권장]**
DXF를 임의 지점에서 truncate/바이트 플립한 입력 100개 → 파이프라인이 크래시가 아니라
"오류 보고 후 정상 종료"하는지. 고객이 보낸 파일은 언젠가 반드시 깨져 있다.

**R-H5. 마이그레이션 왕복 테스트 [권장]**
migration up → down → up 후 스키마 동일성. 데이터 있는 상태에서 up 테스트.

**R-H6. mypy strict + 좌표 타입 [편집증]**
(x, y) 튜플이 (y, x)로 바뀌는 사고는 타입으로 못 잡는다 → `Point2D` NamedTuple로 통일해
위치 인자 실수를 구조적으로 차단. 신규 코드부터 적용.

# PART 10. 프로세스·휴먼 검증 — 나 자신을 의심하라

**P-1. 골드셋 이중 라벨링 [권장]**
혼자 프로젝트라도: 골드셋 20방을 오늘 라벨링 → 2주 후 같은 20방을 원본만 보고 재라벨링 →
자기 자신과의 일치율(intra-rater) 측정. 90% 미만이면 라벨링 기준 자체가 모호하다는 뜻 —
기준 문서를 먼저 고쳐야 한다. (멘토/동료 1인 확보 시 Cohen's κ로 승격)

**P-2. PDF 벡터 직접 추출 = 제3의 소스 [권장] ★저비용 고효율**
제공된 PDF가 CAD 출력 벡터 PDF라면(스캔이 아니면) pymupdf로 **텍스트·선을 좌표째 직접 추출**
가능 — OCR 불필요. DXF/DWG/PDF **3중 대조**가 성립한다: 세 소스의 방번호 집합 비교는
변환 손실·유령 라벨·누락을 한 번에 잡는 가장 강한 교차검증이다. X-41로 등록.
점검: `page.get_text()` 가 비어 있지 않으면 벡터 PDF다. 30분 스크립트.

**P-3. 악마 fixture 세트 [권장]**
일부러 극악 도면을 합성해 상비: 90° 회전 시트, 미러 시트, 중앙정렬 텍스트, frozen 유령 레이어,
점선 철거벽, 곡선벽, 중복 라벨, z 오염, 대좌표. 신규 코드가 이 세트를 통과해야 머지.
악마 fixture 생성 스크립트 자체가 포트폴리오 소재다.

**P-4. 납품 전 체크리스트 강제 [필수]**
verify 전 항목 통과 / 카나리아 diff 클린 / 골드셋 P·R 기준치 / 민감도 리포트 / QUESTIONS 미결
항목 리포트 명시 / AutoCAD 실기 오픈 확인. 체크리스트 파일에 서명(날짜+커밋해시) 남기고 태그.

**P-5. 사후 검시(post-mortem) 루틴 [권장]**
오류가 하류(컨설턴트 검수)에서 발견될 때마다: 왜 22종 교차검증이 못 잡았나 → 잡을 수 있었던
검증을 이 문서에 추가. **검증 목록 자체가 성장하는 구조**가 이 문서의 완성형이다.
