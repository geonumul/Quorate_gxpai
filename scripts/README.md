# scripts 색인

번호는 **쓰임새**다. 1~4는 계속 쓰는 도구, 5~6은 조사하며 쓰고 버린 것이다.

전부 저장소 루트에서 실행한다. 예: `python scripts/1_운영/preview_rules.py f_1ae3a266`

## 1_운영 - 실제로 계속 쓴다

| 스크립트 | 무엇을 하나 |
|---|---|
| `onboard.py` | 새 설계사무소 도면을 받아 프로파일 초안을 만든다. `--try` 는 실제로 flood-fill 을 돌려 방 개수가 상식적인지 확인한다 |
| `preview_rules.py` | **잠긴 규칙을 dry-run** 한다. DB 에 아무것도 쓰지 않는다. 검수 전 규칙이 무엇을 잡을지 볼 때 쓴다 |
| `audit_all.py` | 추출 결과 전반을 훑는다 |

## 2_시트전처리 - 한 DXF 에 겹쳐 그려진 시트를 잘라낸다

참고도면은 같은 평면도에 겹(overlay)을 얹은 시트가 6장이고, 시트마다 x 원점이 다르다.

| 스크립트 | 무엇을 하나 |
|---|---|
| `cut_ref_sheet.py` | 시트 하나를 잘라낸다 |
| `cut_ref_sheet_aligned.py` | 기준 시트 좌표계로 **평행이동해서** 잘라낸다. 차압계, 인터락, 천정기구 시트를 이걸로 가져왔다 |

## 3_교차검증 - 근거가 둘일 때 대조한다

| 스크립트 | 무엇을 하나 |
|---|---|
| `xcheck_arrow_vs_pa.py` | 차압 화살표 방향과 도면에 적힌 절대압력(Pa)을 대조한다. 어긋나면 우리 버그이거나 도면 오류다 |
| `arrow_meaning_analysis.py` | 화살촉이 저압 쪽을 가리키는지 검증한 기록 |

## 4_렌더 - 눈으로 확인한다

자동 판정을 믿지 않는다. 그림으로 본다.
출력은 `artifacts/` 로 간다. **`out/` 에 쓰면 안 된다** (발주처 도면을 그린 것이라 git 에 딸려 들어간다).

| 스크립트 | 무엇을 하나 |
|---|---|
| `render_3f_walls.py` | 벽 레이어별로 무엇이 잡히는지 |
| `render_ref_walls.py` | 참고도면 벽 |
| `render_leak.py` | flood-fill 이 어디로 새는지 |
| `render_door_swing.py` | 문이 못 열리는 곳 |

## 5_도면조사 - 1회성 조사 (26개)

`probe_*`, `diag_*`, `hunt_*`. 도면 구조를 파악하려고 그때그때 짜서 돌린 것이다.
**다시 쓰려고 만든 게 아니다.** 다만 어떻게 알아냈는지가 남아 있어서 지우지 않는다.

무엇을 찾다가 짰는지는 각 파일 맨 위 docstring 에 적혀 있다.

## 6_파라미터튜닝 - 값을 찾으려고 돌려본 것

`try_*`, `tune_*`. 격자 크기, 틈 메우기 거리 같은 값을 실측으로 정할 때 썼다.
**짐작으로 정하지 않는다**는 원칙이 여기서 나왔다.
